# Owned SOURCE writer C ABI: precode contract

This is a contract for a future producer. It contains no header, producer, source
hook or compiled ABI result. D4VR remains research and prototyping: Diablo's
input resource, writer and useful transforms remain unknown, and no usable
Diablo VR presentation has been established.

The next useful result is an original SOURCE observation of the declared view,
binding and emitted writer. The existing Python calculation accepts supplied
facts; the existing translator runtime observed typed descriptor history. Neither
identifies Diablo's writer. Repeating their pixels would not close that gap.

The normative entry point is
[the C ABI manifest](schemas/owned-source-writer-c-abi-v1/normative-manifest.json). Its pinned
contract and annexes specify the proposed layouts, functions, presence rules,
source ownership, status codes, storage and capture boundary. The existing
[wire grammar](schemas/owned-source-writer-v1.json) and pure model remain unchanged.
Layout values are requirements calculated from the declared field types, not
measurements from a C or C++ compiler.

The proposed private namespace is `d4vr_osw_`. A new core owns one context, shared
by source callbacks and six new controls: `D4VR_OwnedWriterBeginV1`,
`D4VR_OwnedWriterSealV1`, `D4VR_OwnedWriterReceiptCopyV1`,
`D4VR_OwnedWriterReceiptRetainV1`, `D4VR_OwnedWriterReceiptDropV1` and
`D4VR_OwnedWriterStatusV1`. These controls accept a nonce, enablement, opaque
tokens and output capacities. They accept no application supplied descriptor,
resource, generation, root state, clock or selection facts.

Despite its name, `Seal` only acquires an ownership alias for an already frozen
frame. The source selects the first factory candidate and first cold Draw before
knowing whether their branches are supported. It cannot skip a singleton or an
unsupported writer to obtain a later positive result. A healthy window ends at
the selected original Execute RETURN. Copy sources are fixed at each COPY ENTRY;
the visible descriptor history is selected at Execute ENTRY. Missing origins,
warm continuation and unsupported native routes remain unknown. A terminal
capture failure may leave no payload; it cannot manufacture an Execute or RETURN.

The sink reads only bounded, owned inline POD values. Original addresses are
observations, not addresses for it to dereference. Actual numeric zero, observed
NULL and an unavailable observation have distinct presence states. In particular,
an unread nullable copy-size operand cannot become a legitimate NULL array.
Release and native Destroy detach their identities and owners before the original
call and do not read a destroyed receiver afterward. Metadata failure or quota
exhaustion must preserve every original call and its result.

The root description must be copied at the genuine generic parser return, before
conversion or free. A stateless shader bridge calls the single core context. The
instrumented shader archive must replace the ordinary archive throughout the new
core's dependency graph; it must not add a second parser or context. The new
`owned_source_writer_observer` option defaults to false. Enabling it together with
the existing `enable_d4vr_typed_copy_source` observer must cause a configuration
error. This contract does not modify either existing DLL pair.

The declared storage is one 404,352-byte context arena plus a separate 64-byte
issuer, with one 65,536-byte immutable payload, a separate serialization workspace
and at most eight ownership aliases. There are 64 retained records, 128 marks,
32 shared pending slots and 21 retained object occurrences. These are protocol
and observer storage bounds, not a bound on compiler stack, original libraries,
all threads or total process memory. No new execution envelope is admitted here.
The old 16 KiB transport is a separate component.

This documentation was reviewed before implementation. The review includes
layout arithmetic, original source lifetimes, return domains and causal test
designs. Those designs are not executed tests. This documentation change does not
rerun the previous CPU suites or any physical experiment. CI224's 1,130 Python
tests and existing native sanitizer results belong to the earlier implemented
model, not to this proposed C ABI.

The next gate is a separately scoped C implementation with mock original
callbacks, independent CPU controls and actual ABI compilation checks. Source
patches, vendor builds and runtime execution each require later review and pins.
Historical API observations still do not establish current descriptor contents,
actual sampling, GPU reads, renderer ownership, backing, game input or VR.
