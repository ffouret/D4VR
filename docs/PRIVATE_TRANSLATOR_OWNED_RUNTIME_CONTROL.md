# Private translator execution in the owned control

The private instrumented translator has now executed in a new owned
application under GE Wine and Steam Runtime. Its original control exports
returned two immutable OUTER receipts during the graphical workload. This is
a laboratory result. Diablo's rectangle and cutouts remain unresolved, and
there is no established Diablo image in Quest or continuous immersive cadence.

The application ran `direct_A_clamp` followed by `after_bind_B_clamp`, once
with the previously built OFF core and once with its ON counterpart. Both
original wrappers returned zero. Each run produced two complete 256 by 144
BGRA images, each 147456 bytes, matching the existing integer oracles. All
294912 corresponding OFF/ON output bytes matched. No old eight-case control
or game run was repeated.

The ON core returned 8844 and 11159 actual ReceiptCopy bytes. Their source
histories contain three and seven typed mutations. The later copy of B occurs
after the original bind and Close and before Seal and Execute. Four selected
SRV getter occurrences and their cached application references join the
original source receipts. The two retained aliases return identical bytes
after normal COM cleanup. All four guarded Copy buffers and every original
control return are preserved in the private evidence.

OFF exposes none of the six diagnostic controls and produces no receipts.
Both modes journal 129 original API/COM occurrences; ON also journals 18
control calls. Their captured argument roles, HRESULTs and original call
schedule agree. Object roles come from original successful creation outputs
and descriptor slots from original getter results. This comparison does not
claim that every original argument was captured or that opaque pointers have
the same identity in separate processes.

The new executable reports its own module paths and the owners of all six
control entry points through original Windows module APIs. The fixture,
forwarder, selected core and DXGI paths match the prelaunch mappings. Disk
hashes of 94 pinned inputs, copies and plans agree before OFF, before ON and
after the pair. These observations do not attest loaded memory, backing
identity or complete import-provider identity. Original installed DLLs were
not replaced.

Each run records one validation activation marker and 25 warning lines. The
complete bounded logs contain no logged VUID or matching validation error.
Warnings and the original logs remain preserved. This does not establish
complete dynamic descriptor-access validation or universal error absence.

The frozen CPU children retain `prototype_only=true`, `vendor_built=false`
and `runtime_executed=false`. Their positive results are calculations on
supplied histories. A new external parent proof separately records the actual
invocations and observations; no old receipt, flag or certificate is promoted.
The source/CPU contract is described in
[PRIVATE_TRANSLATOR_OWNED_EXECUTION.md](PRIVATE_TRANSLATOR_OWNED_EXECUTION.md).

Current descriptor contents, absence of an overwrite, a sampled-resource GPU
read, game input identity, renderer ownership, backing and global API absence
remain unproven. The next question is how to observe useful original view and
binding facts inside the translator for the game. The current bind, Close,
Execute and readback journal belongs to the owned application and supplies no
such game observation.
