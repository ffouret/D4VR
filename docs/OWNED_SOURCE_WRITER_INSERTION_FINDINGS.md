# Owned SOURCE writer insertion: precode findings

D4VR remains research and prototyping. The latest Diablo diagnostic still has the rectangle and cutouts; its actual sampled input, writer and useful transforms remain unknown. No Diablo image in Quest or continuous immersive presentation has been established.

The C-only sink and its CPU controls are implemented and covered by CI232. This document records a later source inspection. It does not report new wrapper code, ABI compilation, vendor configuration/build or execution. The previous successful private translator experiment exercised the older typed-copy route; it is distinct from the proposed writer hooks.

The real source contains two nested `SetPipelineState(initial_pipeline_state)` calls, one in constructor Reset and one in the first case Reset. The owned workload passes NULL as the initial pipeline. These genuine calls were absent from the earlier 61-call mock schedule. They must remain in any faithful SOURCE trace. The frozen model accepts a pending command only for constructor Reset, and requires an existing PSO for SetPipeline. A faithful trace containing these setters therefore cannot support that model's positive relation. Missing generation and observed NULL can still be represented for an unknown diagnostic; this semantic limitation alone does not prove a transport failure.

Conditional source accounting gives 63 calls/126 marks for the ordinary early monolithic path with one `vkCreateDevice` attempt, or 64/128 with two attempts. An early pipeline retry gives 64/128 or 65/130. Broader fallback paths can exceed the object and event caps. These are correlated, conditional source paths, not observed runtime schedules. The actual native branch and complete projected raw/node fit remain unestablished. Caps stay at 64 records, 128 marks, 21 objects and 65536 raw bytes; no truncation, eviction, retagging or cap increase is proposed.

The insertion precode is **not closed and does not admit implementation**. Its remaining work is concrete:

- Define how the stateless parser bridge admits only a genuine pending RootCreate. The current header has no readonly eligibility operation. A newly named query is a proposal, not an existing function. Capture the real generic parser result before ownership transfer, conversion or free.
- Carry the literal GRAPHICS source-site provenance to the actual native layout call. An earlier helper entry cannot replace the native entry. Existing pending-PSO and Lookup owner propagation should be reused where valid; any missing command/epoch provenance needs an explicit finite design.
- Retain both nested setters and preserve the frozen model's complete unknown result. Do not filter calls, invent early births or rebuild the validated model to obtain a positive result.
- Specify a bounded production SHA256 reader for actual source-owned shader spans, with exact lifetime and local-storage rules. Fixture hash functions are not a production source utility; a matching digest does not establish an object's origin.
- Finish the per-site read rules, temporary-storage accounting and dependency proposal. The proposed strict C11 sink lives in one core; the instrumented core-only shader archive replaces its ordinary transitive dependency. Default is OFF, and simultaneous old/new observers must be a configure error. None of that proposed linkage has been configured or built.

The accompanying tables distinguish 46 callback families from their individual source sites, and keep source-derived counts separate from documentary size examples. Independent review and authorship limits are recorded in the proof. This is source evidence and a proposal, not third-party certification.
