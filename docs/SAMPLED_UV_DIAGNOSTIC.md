# Sample-coordinate color diagnostic

This opt-in constructor prepares a private fragment candidate for an owned pixel control. It does not select an override for Diablo, admit a game bundle, identify a sampled game image, or repair the missing wide-field regions.

`tools/sampled_uv_probe.py` requires an explicit original SHA256 and a closed, validated SPIR-V snapshot. The accepted fragment has one linear entry point, six loads, one implicit-LOD sample and four scalar output stores. Its image and sampler indices come from two distinct push words. The constructor takes the **actual sample-coordinate SSA value** and changes exactly the R/G store value operands. The original coordinate, descriptor operands, reads, sample, B/A stores, interfaces and control flow remain unchanged. It adds no load, image operation, store, branch or function. The older contract that preserves every original store value does not authorize this diagnostic.

The encoding is fixed before execution. For finite `t` in `[-1,2]`, the shader computes `(1 + 253*((t+1)/3))/255` in the recorded arithmetic order. Values below/above that interval produce unavailable codes 0/255. Original sampling still uses the original coordinates. NaN and infinity behavior is not certified by these GPU controls. The [Vulkan fixed-point conversion rules](https://docs.vulkan.org/spec/latest/chapters/fundamentals.html#fundamentals-fixedfpconv) allow converting a float to UNORM with either neighboring integer, so the independent oracle admits floor or ceil with an explicit finite-case arithmetic budget. It does not assume round-to-nearest. `decode_interval` returns a conservative interval, never an exact UBO value or texture coordinate; codes 0/255 have no numeric interpretation.

The paired owned fixture supplies the unchanged original vertex and fragment privately, plus the constructed candidate. It uses two known 8×8 textures, two nearest samplers and explicit UBO placement. The CPU oracle derives pixel-center coordinates independently from signed viewport geometry. It checks original BGRA bytes, diagnostic B/A byte equality, R/G bounds, and unchanged nonzero LOAD pixels outside viewport/scissor. Texture-index and sampler-index controls must change B while leaving R/G unchanged; a wrong UBO component must change the encoded coordinate witness. Negative-height viewport and finite overflow cases are separate controls. An additional feature-enabled descriptor-buffer pair exercises known finite descriptor placements. Neither backend establishes how Diablo places descriptors.

The CLI writes private snapshots and reports only after validating the original and result with the pinned SPIR-V policy and validator. `verify_candidate` reconstructs the candidate deterministically and compares its bytes. Repository tests use a separately built, owned SPIR-V fixture. CI validates these static constructions and valid refusals without private shaders, a GPU or a game.

## Original fragment-output declarations

Writer snapshot schema 4 adds independent, bounded original declaration facets for color formats, attachment-zero blend enable/write mask, logic-op enable and rasterization sample count. Each retains its owner, reason masks and chain observations by value before the driver call. The output owner is the fragment-output GPL subset; a lone pre-raster or fragment-shader subset does not authorize reading ignored color state. A sample count is admitted only when the original declaration supplies the required combined ownership. Unsupported dynamic state, render-pass semantics, chains, ambiguous owners and missing values remain unknown. These refusals affect metadata only.

Push-layout and conventional viewport/scissor facets remain independent. Schema 1/2/3 receipts stay historical. A selected lease retains its serialized original snapshot, including unknowns; it is never completed from the current registry or a later pipeline.

A known format/mask/blend declaration is a decoding prerequisite, not proof that this draw last wrote an exported pixel. Coverage, shading-rate effects, effective rasterization, downstream transformations, initialization and GPU execution order remain separate unknowns. A game diagnostic must additionally verify its actual attachment/source chain and refuse numerical interpretation when those prerequisites are missing. A visible gradient alone is insufficient.

## Scope of evidence

The proof linked below describes only the executions actually completed. Owned-resource controls and CPU snapshots must not be relabeled as a Diablo result. The previous real Diablo trial declared a full-source viewport and scissor in seven retained writer draws; it did not identify the sampled input or prove GPU coverage. The central rectangle and outer cutouts remain unresolved. No Diablo image has been submitted to Quest, and no continuous immersive rendering is established.

The completed owned controls are recorded in [sampled-uv-diagnostic-v1.json](proofs/sampled-uv-diagnostic-v1.json) and [fragment-output-declarations-v1.json](proofs/fragment-output-declarations-v1.json). The UV control checked 48 readbacks (707,788,800 bytes) with zero validation errors; the debug callbacks also retained 32 loader warnings. An unused empty descriptor-set offset was rejected in an earlier setup and is preserved as a failed attempt. The final physical per-environment audits remain unchanged; only an aggregate Python tuple/list comparison and its test were repaired afterward, without repeating GPU execution.
