# Sample-coordinate color diagnostic

This opt-in constructor prepares a private fragment candidate for an owned pixel control. A separate dedicated admission can add exactly one closed fragment-content mapping to a fixed monoscopic diagnostic bundle. Neither step identifies a sampled game image or repairs the missing wide-field regions.

`tools/sampled_uv_probe.py` requires an explicit original SHA256 and a closed, validated SPIR-V snapshot. The accepted fragment has one linear entry point, six loads, one implicit-LOD sample and four scalar output stores. Its image and sampler indices come from two distinct push words. The constructor takes the **actual sample-coordinate SSA value** and changes exactly the R/G store value operands. The original coordinate, descriptor operands, reads, sample, B/A stores, interfaces and control flow remain unchanged. It adds no load, image operation, store, branch or function. The older contract that preserves every original store value does not authorize this diagnostic.

The encoding is fixed before execution. For finite `t` in `[-1,2]`, the shader computes `(1 + 253*((t+1)/3))/255` in the recorded arithmetic order. Values below/above that interval produce unavailable codes 0/255. Original sampling still uses the original coordinates. NaN and infinity behavior is not certified by these GPU controls. The [Vulkan fixed-point conversion rules](https://docs.vulkan.org/spec/latest/chapters/fundamentals.html#fundamentals-fixedfpconv) allow converting a float to UNORM with either neighboring integer, so the independent oracle admits floor or ceil with an explicit finite-case arithmetic budget. It does not assume round-to-nearest. `decode_interval` returns a conservative interval, never an exact UBO value or texture coordinate; codes 0/255 have no numeric interpretation.

The paired owned fixture supplies the unchanged original vertex and fragment privately, plus the constructed candidate. It uses two known 8×8 textures, two nearest samplers and explicit UBO placement. The CPU oracle derives pixel-center coordinates independently from signed viewport geometry. It checks original BGRA bytes, diagnostic B/A byte equality, R/G bounds, and unchanged nonzero LOAD pixels outside viewport/scissor. Texture-index and sampler-index controls must change B while leaving R/G unchanged; a wrong UBO component must change the encoded coordinate witness. Negative-height viewport and finite overflow cases are separate controls. An additional feature-enabled descriptor-buffer pair exercises known finite descriptor placements. Neither backend establishes how Diablo places descriptors.

The CLI writes private snapshots and reports only after validating the original and result with the pinned SPIR-V policy and validator. `verify_candidate` reconstructs the candidate deterministically and compares its bytes. Repository tests use a separately built, owned SPIR-V fixture. CI validates these static constructions and valid refusals without private shaders, a GPU or a game.

## Dedicated technical admission

`tools/sampled_uv_admission.py` prepares exactly 5,380 entries: the unchanged 5,379-entry post-depth baseline plus one UV fragment mapping. The baseline passes its original dedicated admission. Its complete directory, override bytes, receipts and ten evidence payloads are copied without rewriting; the new manifest keeps its transport fields. The policy is `fixed_monoscopic_no_xr`, without a depth variant or stereo A/B permission. Matching uses of the original fragment **content** can all change; this does not target one old numeric pipeline. The generic selector and bundle validator remain unchanged, and the generic validator refuses this diagnostic.

The dedicated gate requires eleven explicit SHA256 inputs covering the baseline manifest/admission, inventory, original, candidate, candidate report, GPU aggregate, independent audit, validator and two grammars. It reconstructs the candidate deterministically, repeats full original/candidate module validation, checks the context vertex/fragment/candidate identities from their bytes, and rechecks current source/dependency fingerprints. The physical-before and final audit fingerprints remain distinct: only the reviewed aggregate comparator repair and its test may differ. The two saved GPU environment audits and independent pixel audit must join the same original and candidate. These are the previously completed owned controls, not another GPU execution.

`check_inputs` performs the read-only preflight; `prepare` writes a fresh private directory; `validate_admission` rechecks live input pins, the complete live/copied baseline, evidence, overrides and source fingerprints. Existing-target collisions, a copied original retagged as diagnostic, stale evidence, missing hashes, unsupported modes, symlinks and protected-path traversal are refused. Source and dependency hashes are captured before preflight and checked again before the admission receipt is written.

The recorded parent preparation completed the 5,380-entry bundle and its dedicated integrity gate. Both `combined_bundle_gpu_validated` and `game_bundle_gpu_validated` remain false. The [technical-admission proof](proofs/sampled-uv-admission-v1.json) records 64 portable CPU tests and an independent preflight of the real unchanged baseline with 32 refused alterations. Portable tests mock the full validator, GPU evidence and legacy baseline gate; the independent review uses the already pinned module-validation receipts without launching a validator. The actual preparation repeats the full module checks. A separate read-only review of the prepared artifact rehashed all 10,795 files, confirmed every baseline override and the complete copied baseline, and reused the pinned validation receipts without running a validator. This proof ends at preparation and includes no later game-execution result.

## Original fragment-output declarations

Writer snapshot schema 4 adds independent, bounded original declaration facets for color formats, attachment-zero blend enable/write mask, logic-op enable and rasterization sample count. Each retains its owner, reason masks and chain observations by value before the driver call. The output owner is the fragment-output GPL subset; a lone pre-raster or fragment-shader subset does not authorize reading ignored color state. A sample count is admitted only when the original declaration supplies the required combined ownership. Unsupported dynamic state, render-pass semantics, chains, ambiguous owners and missing values remain unknown. These refusals affect metadata only.

Push-layout and conventional viewport/scissor facets remain independent. Schema 1/2/3 receipts stay historical. A selected lease retains its serialized original snapshot, including unknowns; it is never completed from the current registry or a later pipeline.

A known format/mask/blend declaration is a decoding prerequisite, not proof that this draw last wrote an exported pixel. Coverage, shading-rate effects, effective rasterization, downstream transformations, initialization and GPU execution order remain separate unknowns. A game diagnostic must additionally verify its actual attachment/source chain and refuse numerical interpretation when those prerequisites are missing. A visible gradient alone is insufficient.

## Completed fixed monoscopic game trial

The first admitted game trial completed four successive monoscopic pairs: reference warm/held measurements followed by wide warm/held measurements, yielding eight 2560×1440 BGRA8 exports. The request script took 11.530 host seconds, distinct from the launcher lifetime. The held observations span 5,326 and 5,310 host milliseconds, with 770 and 767 observed present intervals; these are not GPU elapsed times. There was no return phase or depth readback. The game exited through its normal UI, the launcher wrapper returned zero before post-exit probes, all owned game/launcher processes exited, and the original audit with 262 named exports remained identical. No Khronos validation was enabled in the game, and no final global Vulkan teardown/fence counts are claimed.

Across all eight exports, each complete R plane is byte-identical to the other R planes, and each complete G plane is byte-identical to the other G planes. R depends only on horizontal position and G only on vertical position; both are nondecreasing. This regular raw pattern spans the images while the central-rectangle pattern persists in B. These are observations of exported channel bytes, not numerical UV measurements or proof of the final shader writer. Original/candidate B/A pixel equality was not measured in this game trial; the preserved dependency remains a source-code contract backed by the separate owned controls.

An independent CPU audit checked all eight raw exports and seven retained writer states, including their BLIT, lease, stage and prefix bindings. It rehashed 10,839 distinct consulted paths across session inputs, bundle overrides, copied baseline and source files; this is not an export count. It launched no subprocess, GPU work or UI action and modified no source, bundle or recorded evidence.

Seven retained candidate-corresponding draws have known full-source conventional viewport/scissor operands and all five output-declaration facets. Their original pipeline declaration names `VK_FORMAT_B8G8R8A8_SRGB` (50), while source-image creation and the exported capture name `VK_FORMAT_B8G8R8A8_UNORM` (44). Blend and logic-op enables are zero, the write mask is 15 and the declared sample count is one. The actual image-view format and intervening channel operations were not observed. One selected prefix is empty; all eight preserve missing-prefix and pre-admission gaps. These facts do not establish complete GPU writer history or coverage.

Numeric UV decoding is **refused for every export**. The prior owned UNORM output prerequisite is not met by the SRGB declarations; candidate-output-to-pixel provenance, identity downstream operations, and finite-input/nonfinite-behavior evidence are also missing. A gradient or an interior byte cannot clear those gates. The [real-trial proof](proofs/diablo-sampled-uv-v1.json) records these observations separately from the historical admission snapshot.

The prepared next step is a new owned causal comparison of legal UNORM44 and SRGB50 color-output/view paths, including the original BLIT/readout and an independent transfer/quantization oracle. It has not run. It addresses the newly observed format gap; repeating the same game or unchanged old GPU control would not establish that path. Any future model fit to existing game exports would still require pixel provenance and downstream evidence before numeric decoding.

## Scope of evidence

The linked proofs distinguish owned controls, technical bundle preparation and the separate completed game trial. The admission snapshot remains historical. The real trial establishes raw channel patterns and original CPU declarations; it does not identify the sampled input, admit numeric UV decoding or prove GPU coverage. The central rectangle and outer cutouts remain unresolved. No Diablo image has been submitted to Quest, and no continuous immersive rendering is established.

The completed owned controls are recorded in [sampled-uv-diagnostic-v1.json](proofs/sampled-uv-diagnostic-v1.json) and [fragment-output-declarations-v1.json](proofs/fragment-output-declarations-v1.json). The UV control checked 48 readbacks (707,788,800 bytes) with zero validation errors; the debug callbacks also retained 32 loader warnings. An unused empty descriptor-set offset was rejected in an earlier setup and is preserved as a failed attempt. The final physical per-environment audits remain unchanged; only an aggregate Python tuple/list comparison and its test were repaired afterward, without repeating GPU execution.
