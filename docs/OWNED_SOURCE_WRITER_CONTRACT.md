# Owned first SOURCE writer: precode contract

This is a contract for a future CPU calculation on supplied original SOURCE observations. No new calculation, native producer, source hook or runtime test is implemented by this document. Diablo VR remains research: the last game diagnostic still has the rectangle and cutouts, and its actual input resource and writer are unknown.

The frozen minimal SOURCE model remains unchanged. Its one SRV table and single bound heap cannot admit the unchanged owned workload, which has an SRV table, a sampler table, PIXEL constants and two bound heaps. The new grammar preserves that workload instead of removing calls to satisfy the old profile.

The proposed history covers six original resource creations, four heaps and eight getter occurrences. Only two Texture2D DXGI28 resources and three SRV slots participate in the selected declared-view lineage. Upload/readback buffers, the DXGI87 render target, sampler heap and RTV heap retain their original creation and use arguments. Their auxiliary role does not mean that shaders ignore them. No sampler contents or effective shader access is established.

Root parameter 0 is an SRV table, parameter 1 is a SAMPLER table and parameter 2 contains two PIXEL constants. The sampler heap type is 1; its descriptor range type is 3. Both bound heaps, original pointers/counts, raw constant words, original BOOL values and NULL descriptions remain explicit. The original native viewport/scissor callbacks use WithCount signatures and retain actual values separately from the COM raster arguments.

The first window begins before genuine origins and ends after the first case Execute RETURN, before cleanup. The constructor Reset remains an actual nested callback. Its ordinal differs from the later selected Reset; the retained epoch is identified by that later original Reset CallID. No APP/SOURCE clock or generation equality is inferred. The warm second case remains unknown under this one-window contract. Old births/getters are never copied into a new window or hydrated from mutable objects at seal.

A positive supplied relation requires a closed legacy monolithic graphics pipeline chain: one graphics root-layout creation selected by its genuine source callsite, two shader-module births, an original pipeline creation, lookup, bind and direct vkCmdDraw occurrence. Modules must be live during pipeline creation, rather than through Execute. Descriptor-heap, GPL, missing cache origins and unsupported internal/deferred routes remain unknown. The actual branch of the existing physical workload has not been established by this contract.

The selected SRV table history is evaluated at original Execute ENTRY; each descriptor copy freezes its source at its own ENTRY. The final snapshot includes original Execute RETURN. No current descriptor lookup at seal replaces either cut. Code hashes, addresses, labels and draw counts do not manufacture origins or game identity.

The input bound is 64 KiB UTF8, 64 selected records, 128 shared ENTRY/RETURN or observer marks, 4096 value/container nodes and depth 20. One ticket retains one selected epoch; 32 callbacks may be pending. The complete report bound is 256 KiB. These are protocol and serialization bounds, not a bound on all CPU memory. Arrays have independent exact limits in the schema. Overflow, gaps and unsupported facts never justify truncation, eviction, retagging or suppressing an application call.

The accompanying proof distinguishes documentary shape/size measurements from executed inputs. A finite callback-cost envelope and a JSON shape do not attest an actual SOURCE capture, runtime eligibility or every possible input size. All 17 stronger claims remain false, including actual sampled identity, current contents, native descriptor binding, GPU reads, renderer ownership, backing, universal absence and a VR solution.

After the exact schema, source review and quantitative evidence are frozen, the next stage may implement a separate pure calculation and CPU mock harness with independent causal tests. A C ABI, original source producer, static-library sink, private patch, vendor build and physical run each require later gates. No new game or headset session is needed for this stage.

The [exact schema](schemas/owned-source-writer-v1.json) preserves the exact wire grammar of the reviewed final precode candidate, with two explicit prose clarifications: the sole observer is ScopeGap, and copy sources freeze at each COPY ENTRY while the destination history is selected at Execute ENTRY. Its authoring checkpoint labels are preserved; the separate [parent freeze proof](proofs/owned-source-writer-precode-v1.json) records admission for the next CPU implementation stage. Those labels do not authorize a source producer or runtime launch.
